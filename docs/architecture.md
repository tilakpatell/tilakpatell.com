# Architecture notes

Where things live and how the bigger pieces fit. The [README](../README.md) has the overview; [`docs/README.md`](README.md) maps the rest of the docs. This file is a map of the code, not a copy of it: each entry says which module owns what, what is tested, which storage keys and dev hooks exist, and where the design is written down. The rules of the architecture are in [`health/RULES.md`](health/RULES.md). Open work is in the five hand-offs: [Battlefront](superpowers/HANDOFF-battlefront.md), [the galaxy](superpowers/HANDOFF-galaxy.md), [the universe](superpowers/HANDOFF-universe.md), [the worlds](superpowers/HANDOFF-worlds.md) and [the runtime](superpowers/HANDOFF-runtime.md).

## Where things live

- `src/data/` — the single source of truth for roles, projects, skills and education. Every page and the terminal read from here.
- `src/theme/` and `src/index.css` — the company themes (AWS, RTX, Bose, Pendar, Empowerreg, SRC). AWS is the default; the Experience page switches theme as each role scrolls past, and the nav’s switcher pins one for the session.
- `src/components/ambience/` — a live background behind the portfolio pages for each fan theme ([the design](superpowers/specs/2026-10-05-theme-ambience-design.md)). `Ambience.jsx` picks the family (`kinds.js`, tested) and, on a device that can afford it and unless switched off (`setting.js`), mounts `Layer.jsx`, which draws `scenes/<family>.js` through `lib/three/useScene`. Every scene is built on `kit.js`; the company themes get a CSS-only motif in `motifs.css`.
- `src/components/RouteLine.jsx` — the line that draws itself down each page as you scroll. Any `[data-waypoint]` element is a stop.
- `src/components/feed/` — the six portfolio pages as one feed ([the design](superpowers/specs/2026-10-05-feed-design.md)). `feed.js` is the order and the matching (tested); `Feed.jsx` keeps the pages mounted, fetches the next one ahead and moves the address to the page in the middle of the screen. `src/lib/page.js` tells each page whether it is the one on the address and keeps its own search params while it is not.
- `src/stages/` — the live demo on each project page. The Game Boy one is playable.
- `src/components/contact/PaperPlane.jsx` — a paper plane folded from the memo pad (`plane/scene.js`) glides beside the contact heading and leans toward the pointer. The memo form’s send (`tp:memo-sent`) throws it off the screen.
- `src/lib/ai/` — the AI toolkit the worlds’ NPCs share, pure and tested in Node ([the design](superpowers/specs/2026-10-07-npc-intelligence-design.md), [the research](research/2026-10-07-game-ai-npcs.md)). `utility.js` weighs options, `tree.js` is a behaviour tree, `perception.js` keeps what an NPC believes, `search.js` a group search, `steer.js` context steering, `spatial.js` picks a place, `influence.js` maps the battlefield and `squad.js` makes a group act as one. `body.js` and `react.js` turn a brain’s step and the world’s knocks into pose and motion ([the design](superpowers/specs/2026-10-07-living-characters-design.md)).
- `src/lib/three/animator.js`, `clipLibrary.js`, `locomotion.js`, `gait.js` and `animBudget.js` — the animation layer every character goes through (all tested). `clipLibrary.js` names every clip by what it is and retargets it to a figure; `scripts/ual-bake.mjs` bakes the Quaternius clips onto the Meshy rig. `animator.js` is one body per rigged figure (locomotion, base states, layers, a head that looks), `gait.js` the same for figures without clips, and `animBudget.js` steps far figures less often.
- `src/lib/battlefront/` — the Battlefront game’s rules, pure and seeded ([the design](superpowers/specs/2026-10-10-battlefront-game-design.md), [the hand-off](superpowers/HANDOFF-battlefront.md)). `rulebook.js` reads the 2017 game’s data in `src/data/bf2017/`; `nav.js`, `affectors.js`, `abilities.js`, `weapons.js`, `soldier.js` and `bolts.js` are the pieces, and `sim.js` steps them from a seed. `ai/` is the bots; `skirmish.js` and `arena.test.js` fight a 20-a-side battle under `npm run test:ai`, and `scripts/battlefront-balance.mjs --skirmish` prints its table.
- `src/lib/cast/` — the site’s one cast table ([the design](superpowers/specs/2026-10-21-battlefront-by-default-design.md)). `bodies.js` (pure, tested) holds every Star Wars figure kind the site draws, keyed as the galaxy keys them: its file, its height, the rig its loader wants, whose body it is (`source`: `'game'` for the 2017 game’s own, `'mod:<name>'` for a mod’s, `'site'` for Meshy’s, Sketchfab’s, a built one or the 2005 remaster’s) and, on a site row, what could replace it and what stops it (`could`). `bodyOf`, `sourceOf` and `gameFirst` read it, the game’s body first. The galaxy’s `surface/crewList.js` reads it as `CREW`, with the names and the shape it had, so every world names the same body for the same kind. `node scripts/cast-audit.mjs` prints the table and the count by source; the number to move is the site rows with a `could`.
- `src/lib/three/held.js`, `grip.js` and `src/lib/ai/talk.js` — things in hand, and a word on E ([the design](superpowers/specs/2026-10-09-things-in-hand-design.md)). `held.js` (tested) puts an item in a hand read from its own skin; `grip.js` (tested) is the finger curl; `talk.js` (tested) is whom E talks to. `scripts/cast-audit.mjs` audits each figure; `scripts/anim-check.mjs --held --talk` checks it in a browser.
- `src/lib/view.js` and `src/components/ViewSwitch.jsx` — the two views of the site, the universe and the classic pages, and the switch between them. `classicPathFor` and `universePathFor` (tested) land on the same place in the other view. The choice is kept as `tp-start`, which `src/pages/Front.jsx` opens on.
- `src/components/settings/` — the one settings panel ([the design](superpowers/specs/2026-10-07-quality-modes-design.md)). `settings.js` (tested) keeps `tp-settings` and writes the keys the site already reads beside it (`tp-quality`, `tp-3d`, `tp-sound`, `tp-volume`, `tp-sharpness`, `tp-motion`, `tp-ask-download`); `SettingsHost.jsx` opens `Settings.jsx` on `tp:settings`. `src/lib/video.js` (tested) is the picture’s own controls as a schema and store (`tp-video`), drawn by `Video.jsx`; a change reaches the world that is up through the runtime’s `requality` and `revideo`.

## The world runtime

`src/runtime/` is one runtime for the full-screen worlds ([the design](superpowers/specs/2026-10-06-world-runtime-design.md)): one renderer (`webgl.js` on the classic WebGLRenderer; `webgpu.js` on three’s WebGPURenderer for a module whose materials are nodes), one input snapshot a frame (`input.js`), one quality level (`quality.js`), one save store (`saves.js`, versioned), one asset cache with an owner (`assets.js`) and a gain per module (`audio.js`). `runtime()` is made once and kept across routes; `rt.handover` lets the next world take over without a cut (`handover.js`). A world is a module `{ id, shading, mb, create(rt, props) }` (`module.js` checks it); a page mounts one with `useWorld.js` into `WorldHost.jsx`. `shading.test.js` fails a `'nodes'` module whose folder makes a `ShaderMaterial`, patches `onBeforeCompile` or builds an `EffectComposer`. Middle-earth (`components/middleearth/module.js`) is one module showing up to five pictures at once, each a view of the one canvas (`runtime/views.js`). The trip between the galaxy and a surface is flown (`galaxy/travel.js`, `scripts/travel-check.mjs`).

Installs ([the design](superpowers/specs/2026-10-07-infinite-worlds-design.md)): each world declares what it fetches in `src/components/<world>/pack.js`, gathered by `src/components/worlds/packs.js`. `scripts/packs.mjs` writes `dist/packs/<slug>.json` at build and fails on a missed asset (`scripts/pack-check.mjs`); `install.js` fetches a pack into the Cache API as `tp-pack-<slug>-<v>`, and `public/sw.js` (registered by `src/lib/sw.js` only while a pack is installed) answers installed files from it. `WorldGate.jsx` is the front door and `src/pages/Worlds.jsx` the list. Check: `scripts/sw-check.mjs`.

The heavy assets ([the decision](decisions/2026-10-09-heavy-assets-mirrored-on-supabase-storage.md); on Cloudflare R2 since 2026-10-21, [the move](decisions/2026-10-21-heavy-assets-on-r2.md)) are mirrored to the public bucket `site-assets` by `scripts/assets-upload.mjs`, which writes `src/data/assets-manifest.json`. With `VITE_ASSET_BASE` set, `src/lib/assetBase.js` sends those fetches to the bucket and falls back to the site’s own file on the first failure. Check: `node scripts/sw-check.mjs --bucket`.

The chunk services, pure and tested: `chunkGrid.js` (which cells to ask for round a moving point and which to let go), `workers.js` (`rt.workers`, a pool per name with priorities and cancel) and `origin.js` (`rt.origin`, a floating origin moved in whole cells). Minecraft streams its chunks through the first two (`components/minecraft/stream.js`).

The Expanse’s driven planet was a study and has gone ([the design](superpowers/specs/2026-10-08-natural-worlds-design.md)); what it proved stays as shared pieces. `src/lib/land/` makes land as data in a worker (`spec.js`, `layers.js`, `rivers.js`, `cell.js`, `flora.js`, `flats.js`); `src/lib/physics/` is Rapier as data (`world.js`, `heightfield.js`, `props.js`, `vehicle.js`), loaded only by a world that uses it.

The planet flight (`/fly/:planet`) flies a ship low over an endless seeded plane ([the design](superpowers/specs/2026-10-09-planet-flight-and-shared-world-design.md), [the worlds](research/2026-10-09-planet-geographies.md)). It is an island the site can lose in one command: `node scripts/flight-island.mjs --check` runs in `npm test` and `--remove` takes it out ([the design](superpowers/specs/2026-10-10-planet-flight-removable-island-design.md)). Its land is pure in `src/lib/land/flight/` (`biomes.js`, `field.js`, `planetSpec.js`, `quadtree.js`, `leafMesh.js`, `stream.js`, and the tables for landmarks, life and events); the page side is `src/components/expanse/flight/` (`terrain.worker.js`, `ground.js`, `module.js`, `flightRules.js`), where `landmarkScene.js`, `map.js`, `life.js` and `events.js` each stream their layer round the ship.

The WebGPU worlds ([the design](superpowers/specs/2026-10-06-webgpu-worlds-and-living-worlds-design.md), [the stack page](stack/webgpu-tsl.md)) build on `webgpu.js`: a `'nodes'` module draws TSL materials on WebGPURenderer, or on the node renderer over WebGL 2 where the browser has no WebGPU. `src/lib/three/gpuScene/` keeps a level pack’s rows in one storage buffer and culls them in a compute pass, with `surface/level/levelGpu.js` as its door (`createLevelScene({ gpuScene: true })`).

## Graphics

Multiplayer ([the design](superpowers/specs/2026-10-05-multiplayer-across-worlds-design.md)): `universe/online/client.js` is one room on the Nostr relays for everyone online; each walkable world opens a room of its own (`middleearth/towns/useTravellers.js`, `travellers.js`, drawn by `ghosts.js`); a world on the runtime (the Death Star’s inside, the Mario 64 and Minecraft tributes) is handed the link through its module’s `online()` and sends and draws from its own step, and an area of a world (a room aboard, a Cybertron area, a Minecraft seed) is the link’s `area`, so only those in it are listed. A ghost is one look on both renderers (`towns/ghostLook.js`): GLSL on the classic (`ghosts.js`), nodes on the node renderer (`ghostNodes.js`, as `ghostsOf.js`’s `paint`). Every room is joined with the visit’s one key (`nostr.js`), so a traveller’s id is their roster id, and your allies (`online/allies.js`, kept in this browser) are known in every room: a world’s `useTravellers` marks each row `ally`, the ghosts (`ghosts.js`) and the galaxy surface’s peers (`galaxy/surface/peers.js`) wear the ally green, and the players chips count them (`runtime/hud/hud.js`’s `othersText`). `where.js` names each place for the roster. A full-screen world with no travellers of its own hides the page pointers through `useOnline.js`’s `useInWorld`. A room too big to hear whole (the flight’s) is heard by cell through `src/lib/net/cells.js` and `pool.js`’s `refresh()`. `scripts/online-check.mjs` checks it in two browsers on the real relays.

A party ([the design](superpowers/specs/2026-10-19-party-and-quick-chat-design.md)) is up to eight pilots, by invite, on top of allies: `online/party.js` holds its rules (the leader’s roster, epochs, who takes over when the leader goes), `partyLink.js` is the client’s side of it (invites, the roster, Summon, Follow the leader, chat, quips), `partyStore.js` keeps it in this browser (`tp-party`), and `partyWire.js` reads and writes its words. A party mate is a mate as an ally is (`mates.js`’s `isMate`: the ally green, no friendly fire): every place that asked about an ally asks it. The chat is sealed for each mate online (`partyCrypt.js`: secp256k1 ECDH, HKDF, AES-GCM, in the signer worker), so the relays carry blobs; quick chat (`quips.js`) is a set line by its index, public, shown over the player for six seconds wherever they’re drawn: a DOM bubble on the map’s and the galaxy’s tags and the page pointers (`quipBubble.js`), a sprite in 3D (`lib/three/quipSprite.js`) over the worlds’ ghosts, Earth, the galaxy surfaces, the crews on foot and the planet flight. One dialog (`PartyDialog.jsx`, opened by `lib/palette.js`’s `openParty`, from the online corner, the command palette and the players chip in every world’s Menu) holds the party, its chat and quick chat; `PartyHost.jsx` in `OnlineProvider` opens it and shows a summons. `scripts/online-check.mjs --party` checks it in two browsers.

The site is 3D first and lowers its own resolution and effects when frames come late. `src/lib/three/` holds the shared renderer (`renderer.js`, whose `precompile` builds shaders in the background), the `useScene.js` hook that draws only on screen, and `pace.js`, which softens a scene within a second of late frames; `src/lib/gpu.js` checks WebGL once, and only a browser with none gets the SVG and 2D versions. The universe waits for a far planet’s models (`universe/nearby.js`) and signs in a worker (`online/signer.worker.js`). The renderers are three’s classic WebGLRenderer, the node renderer over WebGL 2 and WebGPURenderer with TSL ([the stack page](stack/webgpu-tsl.md)).

Textures and models: every texture goes through `src/lib/three/textures.js` (sharpened, decoded off the main thread, one per URL); every model through `src/lib/three/gltf.js`, one `GLTFLoader` with meshopt and KTX2 (`scripts/ktx2.mjs`; [the measurements](research/2026-10-05-textures-and-asset-quality.md)). `src/lib/three/surface.js`’s `antiTile` hides the repeat on big tiled grounds.

One look ([the design](superpowers/specs/2026-10-07-house-look-design.md)): `src/lib/three/house.js` is the house style every world is on. Shade is a colour rather than grey, fog takes the sky’s colour, and Neutral is the house tone mapper. A world’s ground is data (`src/lib/three/groundmap.js`); grass is `src/lib/three/grass.js`, one draw and a triangle a blade, moved by one wind (`src/lib/three/wind.js`). A world with its own renderer joins in one call, `houseOn`; the galaxy’s surfaces join through `galaxy/surface/look.js` and `groundPaint.js`, with `?debug` putting it all on sliders (`tune.js`). Left as they are on purpose: dot-matrix, Mario 64, Earth, the Ring, the cockpit and the hyperspace jump.

## Phones and device tiers

**The worlds’ kit is Quaternius’s CC0 packs**, imported into `public/kit/<pack>/` by `scripts/kit/import.mjs` (FBX through `scripts/kit/fbx.mjs`), each with an `index.json` from `scripts/kit/manifest.mjs`; `node scripts/kit-check.mjs` holds every pack to its budgets. At run time `src/lib/three/kit.js` loads a pack once and draws its models through keyed instanced pools by the level’s columns in `src/lib/budgets.js`. The manual is [`scripts/kit/README.md`](../scripts/kit/README.md).

**The galaxy’s Battlefront II (2017) models are EA DICE’s, used with permission** ([the decision](decisions/2026-10-10-battlefront-2017-assets.md), [the drop](assets/battlefront-2017.md)). `scripts/bf2017-fetch.mjs` takes a model from the owner’s private bucket into a git-ignored folder under `lab/`; `scripts/bf2017-import.mjs` cuts it for the site and writes its row into `catalog/bf2017.js`, with the pure parts tested under `scripts/lib/`. No visitor ever reaches the bucket. `scripts/bf2017-textures.mjs` gives the surfaces’ roles the game’s own maps, worn through `src/lib/three/scans.js`. Every KTX2 is stamped with its colour space (`scripts/bf2017-colour-check.mjs --check`; [the decision](decisions/2026-10-10-game-maps-say-their-colour-space.md)).

**The galaxy’s vehicles are the game’s too** ([the cast](superpowers/evidence/bf2017-vehicles/cast.md), `scripts/bf2017-vehicles.mjs`): a catalogue group of their own, `catalog/bf2017-vehicles.js`. The walkers and the droideka play the game’s clips on its skeletons (`src/lib/three/ownRig.js`), packed by `scripts/bf2017-rigclips.mjs`; `scripts/bf2017-fleet.mjs` writes the space layer’s fighters and capitals.

## The durable world

What players build on a planet outlives the visit in Supabase ([the decision](decisions/2026-10-09-supabase-for-durable-shared-state.md)). The schema is `supabase/migrations/` and the seed `supabase/seed.sql` (from `scripts/supabase-seed.mjs`; applying both: `supabase/README.md`). The client is `src/lib/durable/`, pure of three.js and React: `supabase.js` makes the one client from `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, or `null` when the build has neither; `entities.js` is the 2048 m grid and the row shape; `entityLoader.js` asks for a planet’s entities a cell at a time and folds Realtime’s changes in. Its tests run against `src/lib/durable/fixtures/fakeClient.js`; `scripts/supabase-check.mjs` walks the real project. Only the anon key reaches the page; row-level security guards the data.

The shared world over a planet is `src/components/expanse/flight/shared.js`, composing two paths that never mix: the room (`online.js`, heard by cell through `src/lib/net/cells.js`; `flightProtocol.js` is its wire) and the durable store. `turretRules.js` runs every turret against every ship and `buildRules.js` grounds a thing built on an older ground. `node scripts/online-check.mjs --fly` checks it on fake relays and a fake store (`scripts/lib/fake-durable.mjs`).

## Hosting

**The site is static, and Cloudflare serves it** ([the decision](decisions/2026-10-21-cloudflare-for-the-site.md), [the page](stack/cloudflare.md)). `.github/workflows/deploy.yml` lints, tests and builds `main`, then uploads `dist/` to the Worker `tilakpatell-com`, tilakpatell.com's custom domain (`wrangler.jsonc`: its files, with code for `/audio/*` alone, `cloudflare/worker.js`, which answers a `Range`). The headers are `public/_headers`'. GitHub Pages served the site until 2026-10-21. The heavy assets are still the Supabase bucket's (above) until they move to R2.

## Tests

`npm test` runs the games’ rules and every pure module beside them (Vitest, each file under a second); CI runs it on every pull request and again before deploy.

The AI and the models are tested end to end in tiers ([the design](superpowers/specs/2026-10-07-ai-e2e-testing-design.md); `scripts/ai-e2e/README.md` is the manual):

- `npm run test:ai` (`vitest.ai.config.js`), CI’s `AI` job on every pull request: the pipelines with fake engines, the shipped models and voice lines, every brain scripted and fuzzed, the autopilot’s guards.
- `npm run test:ai:render` (`vitest.render.config.js`): every gen3d model rendered headless, on a pull request that touches a model and every night.
- `npm run test:ai:gpu`, on the desktop: the judges against labelled sets, one real model and one real line made start to end.
- `.github/workflows/ai-health.yml` runs the GPU tiers nightly on the desktop’s runner and keeps one issue labelled `ai-health`; `node scripts/desktop/status.mjs` shows the last night.
