# Lane S: the lightsaber as the 2017 game's. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (one session, task by task; no review loops: the owner wants speed and direct work). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every saber fight on the galaxy's worlds runs the 2017 game's rules from its records: the hit query, the capsule hitboxes, the damage with its delay and from-behind bonus, the block as the shield sphere with stamina, the dash with its charges, the clash, the camera; one path, on the game's rig, for you and the bots; Ahsoka off the saber roster until she arrives on the game's rig.

**Architecture:** a rulebook (`src/data/bf2017/saber.json`) from an extractor (`scripts/lib/bf2017-rulebook-saber.mjs`), a pure engine (`src/lib/combat/saber2017.js`) over it, and `surface/saber.js` cut to the walrus path and made to draw what the engine decides.

**Spec:** `docs/superpowers/specs/2026-10-10-bf2017-saber-mechanics-design.md` (read it whole first; its records table is your map of the export).

## Global constraints

- Start from `main` (merge `origin/main` before the PR; lanes F, A, H, 1, 5 are running: F owns the deploy screen and reads a hero row's `soon`; H's HvV takes your engine later).
- Own: `src/components/galaxy/surface/{saber.js,saberRules.js,saberGame.js,gameStance.js,stanceFromTable.js,combatRules.js,duellists.js,heldBlade.js,blockSide.js,saberLight.js}` and their tests, `src/lib/combat/{duel.js,blade.js,saber2017.js}` and tests, `surface/boltPlay.js` (the guard test only), `surface/scene.js` (the saber calls, the combat event's new fields, the camera numbers), `surface/HeroPanel.jsx` or `DeployPanel.jsx` (the saber key text and Ahsoka's `soon`; coordinate with lane F by merging main), `src/components/galaxy/heroes.js` (Ahsoka's row, `STANCE_IDS`), `scripts/bf2017-data.mjs` (the `saber` command, additive), `scripts/lib/bf2017-rulebook-saber.mjs`, `scripts/fixtures/bf2017/data/Gameplay/...` (cut records), `src/data/bf2017/saber.json`, `NOTES.md`.
- Numbers from the rulebook; a `hand` value with a `NOTES.md` line. No sequel heroes. Files under 800 lines (`saber.js` is 718: cutting the non-walrus path gives room; split `saberDraw.js` off if needed). British spelling, curly quotes; one plain-sentence commit per task; `npm run lint`, `npm test`, `npm run build`, `node scripts/health.mjs --check --skip build`, `galaxy-check surface hoth` with `BUDGET=1` before the PR.
- The records: in the cloud, `node scripts/bf2017-fetch.mjs data '<glob>'` with `SUPABASE_URL` and `SUPA_KEY` from the environment (`NODE_USE_ENV_PROXY=1`; never print the keys); the index is `data.tsv`. A record's leaves are easy to read with a flatten script (`objects[i].Field = value`); the logic graphs' `PropertyConnections` say which filter feeds which query: follow `$ref`s.

### Task 2: The engine

**Files:** `src/lib/combat/saber2017.js` (+ test).

- [ ] `createSaberSim(rules, { hero, seed })` → `{ strike(now, { dir, clip }), block(on), dash(now, dir), throwSaber(now) (Vader, Maul), step(dt, now, { me: { at, yaw }, targets: [{ id, at, yaw, capsules, deflecting, shielded, dead }], bolts }), state: { stamina, dashes, dashAt, blocking, staggeredUntil, blockedUntil, striking: { clip, t0, contact, delay, hitSet } }, events }`.
- [ ] `hitsFor(me, strike, targets)`: the sphere then the cones in the attacker's facing (from the rulebook, in the order the graph joins them), shielded out, once per strike; a hit carries `fromBehind` and `damage` (initial + behind), applied at `t0 + contact[0] + delay`.
- [ ] `blockOf(me, target)`: the shield sphere (radius, offset along facing) and the front arc; `boltHits(bolt)` for `boltPlay.js` (segment against the sphere while blocking, the deflected bolt's new heading auto-aimed at the shooter).
- [ ] Stamina: drain per bolt and per blocked strike, refill after the pause, break at zero with the stagger; the dash's charges and recharge; `BlockedLightSaber` on the attacker; the clash.
- [ ] Tests as the spec's list; a seeded two-sim duel runs the same twice.
